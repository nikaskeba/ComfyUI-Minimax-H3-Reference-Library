# H3 audio-range inpaint experiment

## Edit video and audio together after generation

Load `example/video_experiment.json` after restarting ComfyUI. Use **Load Video** to upload the video with the soundtrack you want to edit. The workflow trims it to an H3-compatible length, encodes its frames and audio as one AV latent, and feeds that latent to **SKEBA H3 Video + Audio Inpaint Range (Experimental)**. The node has independent `video_start_seconds` / `video_end_seconds` and `audio_start_seconds` / `audio_end_seconds`, plus separate mask strengths. The example starts at **1–3 seconds** for both because its sample clip is short; set both to **4–8 seconds** when your uploaded video is long enough. Video strength starts at **0.25** and audio at **1.0**. `sampling_denoise` controls the shared sampling level.

The node passes its result to the video and audio decoders. The separate MP3 and saved video therefore both use the edited source audio. A status display reports the effective video and audio intervals. H3 video latents cover one frame in the first token and four frames per later token at 24 fps, so the effective visual interval may extend a few frames beyond the requested seconds. The original source latent values outside each selected range are restored exactly, although video/audio VAE decoding may influence pixels or samples near an edit boundary. Use a 24 fps source video with an audio track; this workflow keeps the tested source-video encoding and trimming path from `example/video_inpaint.json`.

This is a sampling pass on the uploaded source video's encoded latent. The 0.25 video mask is an experiment for small appearance or mouth-motion changes, not a guarantee of accurate lip sync. Edit the example prompt to request the desired dialogue and visual response. Start with one short clip and compare the result with the source. If speech changes without enough corresponding motion, increase video strength gradually. If the character or background changes too much, reduce it or shorten the video interval. The source song can also change inside the audio interval.

### Test voice borrowing from source speech

`example/video_experiment_edits.json` uses a 3–8 second edit with `sampling_denoise=0.8` and audio mask strength `0.7`. The earlier pre-sampling audio workflow instead used a full `denoise=1` schedule and a **0.5 audio mask**. That fractional mask keeps more of the source audio latent available during the edit. To separate the mechanisms, load these copies in order:

1. `example/video_experiment_latent_context.json` keeps your source-video chain and 3–8 second ranges. It uses `sampling_denoise=1.0`, audio mask strength `0.5`, video mask strength `0.25`, and the `res_multistep` sampler used by the earlier audio workflow. It uses **only the source AV latent**, with no added reference slot. Its seed is fixed for comparison.
2. `example/video_experiment_audio_focus.json` opens the selected audio span fully with audio mask strength `1.0`. This tests stronger replacement, but may borrow *less* of the source voice because less original audio is held inside the edit.
3. `example/video_experiment_voice_reference.json` adds a separate, selectable 0–3 second source soundtrack sample as H3 `<Audio 1>` conditioning. This is a different mechanism from latent context and is an optional comparison, not a substitute for it.

Choose a `VOICE SAMPLE` range containing clear speech by the person whose voice should carry into the new line. If it contains mostly music, silence, or another speaker, the explicit reference is unlikely to help. Compare each saved MP3 as well as the video. A source-audio latent and an explicit voice reference are different conditioning paths; neither guarantees exact voice cloning or exact words.

## Edit during the normal generation pass

`example/audio_pre_inpaint_experiment.json` is the first workflow to try for music plus added speech. It adds **SKEBA H3 Audio Edit Mask (Before Sampling)** after the supplied music has been VAE-encoded and packed with the video latent, before the base sampler. The node locks the music outside `edit_start_seconds`–`edit_end_seconds` and sets the audio noise-mask strength inside that window (0 = keep music, 1 = fully regenerate). The existing video mask is left alone, so video generation still runs normally. The upscale pass has a second Edit Mask at strength 0 to keep the base pass's edited sound rather than editing it again.

This uses the workflow's existing base and upscale passes; it adds no extra diffusion pass. Update the prompt to request the exact speaker and dialogue over continuing music. The supplied example prompt currently forbids speech. The extra MP3 save node captures the generated sound for listening. In this experimental copy, **Save Combined Video** now takes the combined generated clips directly; the original-song overlay is disconnected. An audio mask changes the whole sound in the selected interval, not an isolated voice stem: music may change there too.

For a diagnostic first run, use a single short clip, set the edit interval to its full available audio duration, and set `audio_mask_strength` to **1.0**. Check the Edit Mask status output for the effective interval and listen to the separate `audio_pre_inpaint_test` MP3. The prompt must explicitly request an audible spoken line; the supplied music-only prompt forbids one. A noticeable difference establishes that the generated-audio path is working. Then try 0.75 and 0.5 to see how much of the song survives. A 0–15-second range on a 15-second source leaves no protected music interval, so it cannot guarantee preservation of the original track. If the separate MP3 remains sample-for-sample unchanged at strength 1.0, inspect the sampler's input mask and the audio output path rather than tuning the prompt further.

**H3 Regenerate Complete Source Audio** is a different control experiment: its implementation locks the whole source video and sets the complete audio mask to 1 on a fresh target audio latent. It asks H3 to synthesize a new soundtrack; it does not use the supplied song's encoded audio as a soft latent seed. This Edit Mask keeps the supplied song latent in the selected interval, then permits denoising there. Neither method provides separate music and voice controls. If the music must remain exact while speech is added, mix a generated speech track with the original song after generation.

## Edit after a completed generation

`SKEBA H3 Audio Inpaint Range (Experimental)` resamples only a selected time interval in an existing, sampled H3 joint video/audio latent. It freezes the video latent and restores the original audio latent exactly outside the interval. The interval uses H3's 40 audio-latent frames per second; boundaries are therefore rounded to 25 ms steps. This is an experimental way to change a spoken line or repair a short audio defect, not a guaranteed transcript editor.

For a first test, load `example/audio_inpaint_experiment.json` and run one short prompt. It is a copy of `audio_workflow.json` with the new node inserted between the upscale `SamplerCustomAdvanced` (node 358) and `Set_sampler_output` (node 423). Its model, positive conditioning and negative conditioning come from the same sources as `CFGGuider` (node 357). Set `edit_start_seconds` and `edit_end_seconds` around the old line, allowing a little time before and after the words; start with `audio_denoise` around 0.65 and `replace_locked_audio` on. Turn `enabled` off for an exact pass-through comparison. Keep `boundary_latent` disconnected for this first speech-replacement test because the workflow's source audio is already locked by a zero noise mask; a boundary mask would protect that region from editing.

Change the generation prompt so it explicitly describes the new spoken line and speaker. The current example prompt says no character speaks and supplies a music track, so it is not a speech-editing test until those are changed. Use a clip with an existing H3 video latent as the source; H3 audio sampling requires a joint AV latent even when only sound is edited.

The experimental copy saves the output of `VAEDecodeAudio` (node 299) through a separate `Save Audio (MP3)` node. Its final **Save Combined Video** also takes the combined generated clips directly. The original-song `ConcatenateVideo` (node 470) is disconnected in this copy, so it cannot hide the inpaint result.

The video latent and non-edited audio latent remain unchanged. Audio-VAE decoding can still affect samples close to the edit boundary. For a production edit, splice the decoded replacement interval back into the original waveform with a short crossfade and retain the original samples everywhere else. Exact words and voice identity are model-dependent; if the line must be exact, generate that speech with a dedicated speech model and splice it into the audio track instead.
