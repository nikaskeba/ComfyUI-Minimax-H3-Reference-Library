# Source video plus audio inpaint experiment

Open `example/alternative_video_audio_inpaint_wired.json` after restarting ComfyUI. It is a copy of `alternative_vida0_inpaint_experiment.json`; the uploaded original was left unchanged.

The uploaded video now supplies both streams. Its audio still follows the existing normalize → trim → audio VAE → audio edit mask path. Its frames are trimmed to the generated frame count, resized to the base-pass dimensions, encoded through the workflow's video VAE, and used as the base-pass video latent. A new **SKEBA H3 Video Edit Mask** is placed before the existing audio edit mask. Its initial 3–10 second window and 0.25 mask strength allow a lighter video edit while the audio edit remains at strength 1.0. Outside the selected video interval, the source-video latent is locked for the base pass.

Adjust the video start/end and strength on the new mask node. Keep the source loader at 24 fps, and ensure it loads at least as many frames as the generation-frame expression requests. The current 260-frame cap covers this workflow's single 10-second prompt. A source shorter than the requested generation will not be extended automatically. The video VAE encode can use substantial memory at 1344 × 768.

The base-pass result feeds the latent upscaler. That upscaler returns only the upscaled samples and discards the base video noise mask. The upscale sampler previously ran at 0.4 denoise with the whole video editable. A second **SKEBA H3 Video Edit Mask** now sits between the upscale AV concat and the existing upscale audio-lock node. Its strength defaults to **0**, locking the entire upscaled video from further diffusion while retaining the upscaler's spatial enlargement. Increase it cautiously (for example 0.05–0.15) only if the enlarged picture needs more diffusion refinement. The audio remains locked in the upscale pass. The learned upscaler itself can still change fine details, so this setting specifically isolates the effect of the second sampler. This graph has structural and mask unit tests, but has not been rendered with the H3 model here.

## Face-shift comparison

The base sampler has two outputs: the actual sampled latent and an intermediate denoised estimate (`x0`). The original upscale branch used the denoised estimate. Test `example/alternative_video_audio_inpaint_sampled_handoff.json` first: it changes only that handoff to the actual sampled output while keeping the learned 3D upscaler. Decode before and after upscaling with the same seed and prompt.

If faces still shift, test `example/alternative_video_audio_inpaint_conservative_upscale.json`: it keeps the sampled-output handoff but replaces the learned 3D upscaler with ComfyUI's bilinear spatial latent upscale at the same 1.5× factor. It does not invent facial detail, so the result may be softer. The video and audio locks still prevent second-pass diffusion. Comparing these two outputs isolates whether the learned upscaler changes identity. Neither has been rendered locally with the H3 model.

The user's `inpaint_mask_test.json` uses the installed `minimax_h3_bf16_CONSERVATIVE_v5.safetensors` learned upscaler with `keep_proportion` enabled. `example/alternative_video_audio_inpaint_conservative_v5.json` brings those settings into the sampled-output version of this experiment. Test it after the sampled-handoff variant: the only difference between those two is the learned upscaler model and its aspect-ratio setting. The reference workflow also restores a painted spatial inpaint mask before its upscale sampler; this experiment instead locks the entire upscaled video and audio there, a stricter protection that avoids needing a painted mask.

## Edit through the padded tail

`[s=10]` is rounded to 243 frames by this workflow's H3 grid expression, which is 10.125 seconds at 24 fps. A video edit ending at exactly 10.0 seconds can therefore leave final video-latent tokens protected, showing source frames at the tail. The base **SKEBA H3 Video Edit Mask** now has **Extend to last frame** enabled in all comparison workflows. It masks every remaining video token after the chosen start, regardless of the nominal end time. The connected display shows `masked_video_tokens` and `video_token_count`; the masked range should end at the total token count. This changes only the video interval; the audio edit window remains 3–10 seconds unless changed separately.

## Restore upscale refinement carefully

The fully locked conservative-v5 test has upscale video mask strength 0, so the second sampler cannot add detail. `example/alternative_video_audio_inpaint_v5_gentle_refine.json` changes that mask to 0.12 from 2 seconds through the final frame, keeping the audio mask at 0. It still passes the completed base sampled latent into the conservative-v5 upscaler. Compare face identity and texture with the fully locked version using the same prompt and seed. If 0.12 is too weak, raise it gradually; stronger second-pass diffusion can change faces again.

`example/alternative_video_audio_inpaint_v5_x0_gentle_refine.json` is the same test except that it passes the base sampler's denoised estimate into the upscale path, matching the handoff style of `inpaint_mask_test.json`. Compare it only after the sampled-output gentle-refinement version, so the handoff is the sole changed variable. These variants have not been rendered locally.

`example/alternative_video_audio_inpaint_v5_anchor_blend.json` keeps the completed sampled output and conservative-v5 model, then blends the learned upscale with a bilinear spatial enlargement of the completed base video latent. The **SKEBA H3 Video Latent Anchor Blend** starts at 0.30 anchor strength (30% base identity anchor, 70% learned upscale). Audio bypasses this blend unchanged. The upscale sampler retains the gentle 0.12 video mask and locked audio. Raise the anchor toward 0.5 if learned upscale faces still drift; lower it toward 0.15 if detail becomes too soft. This is a latent interpolation experiment, not a guarantee of exact face identity; evaluate the rendered result against the fully learned and fully locked comparisons.
